# Перенос RemoteIt на другой сервер

Релиз состоит из двух независимых частей:

1. публичного исходного комплекта конкретной версии без секретов и рабочих данных;
2. закрытого state-архива, который создаётся на действующем VDS непосредственно перед переносом.

В GitHub и в обычный release-архив не входят `.env`, пароли, приватный Android-ключ, база PostgreSQL, SSH-ключи и временные файлы передач.

## Что сохраняет state-архив

- полный dump PostgreSQL: пользователи, устройства, токены, права, журнал, задания и история сеансов;
- `/opt/genesisit/shared`: закрытый `.env` и Android signing-файлы;
- содержимое Docker volume `remoteit_transfers` для незавершённых/готовых передач;
- контрольные суммы SHA-256 и идентификатор исходного релиза.

State-архив содержит секреты. Храните его как пароль от всей системы: права `0600`, закрытое хранилище и отдельная зашифрованная копия.

## 1. Создание переносимой копии на старом сервере

Запускайте в согласованное окно обслуживания: экспорт на короткое время останавливает только контейнер `app`, чтобы dump БД и файлы передач соответствовали друг другу. PostgreSQL и Caddy не пересоздаются, volumes не удаляются.

```sh
sudo install -m 0750 ops/remoteit-export-state /usr/local/sbin/remoteit-export-state
sudo /usr/local/sbin/remoteit-export-state /opt/genesisit/exports
```

Скрипт вернёт пути к архиву и `.sha256`. Скопируйте оба файла на защищённый носитель и проверьте:

```sh
sha256sum -c remoteit-state-YYYYMMDDTHHMMSSZ.tar.gz.sha256
```

## 2. Подготовка нового VDS

- Ubuntu 22.04/24.04 или совместимый Linux x86-64;
- Docker Engine с Compose v2;
- DNS домена направлен на новый IP;
- входящие TCP `22`, `80`, `443` и UDP `443`;
- исходный release распакован в `/opt/genesisit/releases/<version-or-timestamp>`;
- `/opt/genesisit/current` является symlink на этот release.

Не копируйте `.env.example` поверх сохранённого `.env`: рабочие секреты восстановит state-архив.

## 3. Восстановление на пустом сервере

Скрипт принципиально отказывается работать, если обнаруживает существующие контейнеры проекта или таблицы в БД. Флаг подтверждает только то, что целевая система действительно новая.

```sh
sudo install -m 0750 ops/remoteit-restore-state /usr/local/sbin/remoteit-restore-state
sudo /usr/local/sbin/remoteit-restore-state /root/remoteit-state-YYYYMMDDTHHMMSSZ.tar.gz --confirm-empty-target
```

После восстановления проверьте:

```sh
cd /opt/genesisit/current
docker compose -p genesisit --env-file /opt/genesisit/shared/.env ps
curl -fsS https://supportgenesis.ru/healthz
```

Проверьте вход владельца, список устройств, один терминальный запрос и тестовый удалённый сеанс. Агенты сохраняют свой Remote ID и ключ устройства, поэтому после переноса домена на новый VDS подключатся к восстановленной базе без переустановки.

## 4. Если меняется домен

Измените `REMOTEIT_PUBLIC_URL` в закрытом `/opt/genesisit/shared/.env`, домены в `Caddyfile`, DNS и пересоберите новый release. Старые агенты, в которых зафиксирован прежний URL, потребуют обновления либо сохранения редиректа/доступности прежнего домена. Наиболее бесшовный перенос — сохранить `supportgenesis.ru` и поменять только DNS.

## Аварийный откат

До переноса не удаляйте старый VDS. Уменьшите TTL DNS заранее. Если проверка нового VDS не прошла, верните DNS на старый IP; старый сервер и его volumes экспорт не удаляет и не изменяет.
