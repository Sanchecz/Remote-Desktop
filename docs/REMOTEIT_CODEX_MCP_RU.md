# RemoteIt MCP для Codex

RemoteIt MCP — локальный мост между Codex на доверенном компьютере администратора и панелью RemoteIt. Он позволяет находить устройства по имени или Remote ID, читать их состояние, готовить план административного действия и отслеживать результат.

## Принцип работы

1. Владелец или администратор RemoteIt создаёт личное подключение в разделе «Настройки → AI-администратор».
2. На компьютере, где установлен Codex, запускается локальный `RemoteIt-MCP.exe` (Windows) или `remoteit-mcp-linux-amd64` (Linux).
3. Codex обращается к локальному MCP-процессу по STDIO. MCP передаёт запросы на HTTPS API RemoteIt.
4. Сервер проверяет ограниченный токен, актуальную роль владельца/администратора и параметры действия.
5. Диагностика без изменения системы может быть поставлена в очередь сразу. Любое изменяющее действие остаётся в состоянии «Ожидает подтверждения».
6. Владелец или администратор читает точный план в веб-панели и подтверждает его вручную.
7. Сервер подписывает задание Ed25519. Agent проверяет подпись, закреплённый публичный ключ, целевое устройство, срок, одноразовый nonce и хеш параметров до выполнения.
8. Результат и ошибка возвращаются в RemoteIt и остаются в журнале.

Remote ID служит удобным идентификатором устройства, но не является секретом и не даёт доступ сам по себе.

## Готовое подключение на доверенном компьютере администратора

Рекомендуемый способ не требует вручную копировать токен или собирать команду:

1. Войдите в RemoteIt как владелец или администратор.
2. Откройте «Настройки → AI-администратор».
3. Задайте понятное имя подключения и срок его действия.
4. Нажмите «Скачать и подключить для Windows».
5. Запустите полученный `RemoteIt-AI-Administrator-Setup.cmd` на доверенном компьютере, где установлен Codex.
6. После сообщения об успешном подключении перезапустите Codex, только если RemoteIt не появился в списке MCP автоматически.

Персональный установщик сам находит реальный `codex.exe`, скачивает `RemoteIt-MCP.exe`, сверяет его SHA-256, заменяет прежнюю запись `remoteit` и после успешной настройки удаляет себя. При ошибке файл остаётся для диагностики. Если файл был отправлен не тому человеку или потерян, немедленно отзовите соответствующую интеграцию в RemoteIt.

На этой же странице доступна кнопка «Инструкция для другого Codex». Она скачивает готовый русский `.txt` без токенов и паролей: администратору остаётся вписать Remote ID и задачу. Сам персональный файл подключения следует передавать только тому владельцу или администратору, для которого он создан.

## Ручная установка и Linux

Ручной способ нужен только для Linux, нестандартного расположения Codex или диагностики:

1. Создайте личную интеграцию в «Настройки → AI-администратор».
2. Скачайте MCP для своей ОС и проверьте SHA-256 по `/downloads/SHA256SUMS.txt`.
3. Выполните сформированную в панели команду. Общий вид для Windows:

```powershell
codex mcp add remoteit --env REMOTEIT_URL="https://your-remoteit.example" --env REMOTEIT_INTEGRATION_TOKEN="<TOKEN>" -- "C:\RemoteIt\RemoteIt-MCP.exe"
```

Для Linux:

```bash
chmod 700 /opt/remoteit/remoteit-mcp-linux-amd64
codex mcp add remoteit --env REMOTEIT_URL="https://your-remoteit.example" --env REMOTEIT_INTEGRATION_TOKEN="<TOKEN>" -- /opt/remoteit/remoteit-mcp-linux-amd64
```

После добавления перезапустите Codex, если сервер не появился автоматически.

## Краткая инструкция для другого Codex

После установки готового подключения передайте другому Codex следующий запрос, заменив значения в угловых скобках:

```text
Используй RemoteIt MCP.
Целевое устройство: Remote ID <REMOTE_ID>.
Задача: <ЧТО НУЖНО СДЕЛАТЬ>.

Сначала найди устройство и проверь его текущее состояние. До любого изменения
подготовь план, назови точную цель, риск, проверку результата и способ отката.
Предпочитай типизированное действие RemoteIt. script.execute используй только
если подходящего действия нет, и покажи полный сценарий до создания задания.
Ничего изменяющего не считай выполненным, пока владелец или администратор не
подтвердил задание в RemoteIt и MCP не вернул фактический результат.
```

Другому Codex не нужно сообщать адрес API, токен или путь к MCP: всё это уже находится в персонально установленной конфигурации. Remote ID не является паролем, но перед выполнением Codex обязан сверить имя, ОС и текущий статус найденного устройства.

## Инструменты MCP

- `remoteit_list_devices` — список устройств и поиск по имени, IP или Remote ID.
- `remoteit_get_device` — текущая инвентаризация одного устройства.
- `remoteit_plan_action` — проверка параметров, точный план, риск и откат без запуска.
- `remoteit_create_action` — создание аудируемого задания. Изменения не могут быть одобрены через MCP.
- `remoteit_get_action` — состояние, вывод и метаданные задания.
- `remoteit_cancel_action` — отмена своего ожидающего или ещё не полученного Agent задания.

MCP намеренно не содержит инструмента подтверждения или скрытого выполнения. Универсальный сценарий можно подготовить через `script.execute`, но его полный текст показывается в панели, имеет критический риск и запускается только после отдельного подтверждения владельца.

## Базовый каталог действий

- `diagnostic.system` — система, CPU, память, диски и uptime.
- `diagnostic.network` — интерфейсы, адреса, маршруты и DNS.
- `diagnostic.services` — остановленные или ошибочные службы.
- `service.restart` — перезапуск одной указанной службы; требуется подтверждение.
- `process.terminate` — завершение одного PID; требуется подтверждение.
- `file.download` — HTTPS-загрузка в изолированный staging-каталог с обязательной проверкой заранее известного SHA-256; файл не запускается.
- `package.install` — установка одного точного ID пакета через штатный менеджер Windows, Linux или macOS.
- `local.group.add_member` — добавление существующей учётной записи в локальную группу; критическое действие подтверждает только владелец.
- `windows.vpn.upsert` — создание или обновление встроенного VPN-профиля Windows без передачи пароля или общего секрета.
- `system.reboot` — подтверждённая перезагрузка с минутной задержкой.
- `script.execute` — универсальный сценарий PowerShell/CMD/Bash/sh/zsh до 16 КиБ, когда типового действия ещё нет. Полный текст и SHA-256 показываются владельцу; сценарий нельзя подтвердить через Codex.

Предпочтительный путь — типизированные действия: они лучше проверяются и имеют понятный откат. `script.execute` оставляет возможность выполнить практически любую обоснованную административную задачу, но не является скрытым удалённым shell: Agent принимает только подписанный одноразовый конверт, сервер сохраняет точный текст, владелец видит его до запуска, а результат попадает в журнал. Пароли, токены, приватные ключи и другие секреты в сценарий передавать нельзя.

## Примеры запросов Codex

```text
Найди компьютер с Remote ID 244755490 и покажи его состояние.
```

```text
Для Remote ID 244755490 сначала подготовь план диагностики сети, затем запусти диагностику и дождись результата.
```

```text
Подготовь перезапуск службы Spooler на Remote ID 244755490. Ничего не выполняй без моего подтверждения в RemoteIt.
```

```text
На Remote ID 244755490 подготовь установку пакета 7zip.7zip. Сначала покажи план; выполнять можно только после моего подтверждения в панели.
```

```text
На Remote ID 244755490 подготовь встроенный VPN Windows с именем Office и сервером vpn.example.org по IKEv2/EAP. Не добавляй логин или пароль.
```

Если запрос нельзя выразить типовым действием, Codex может подготовить `script.execute`. Полный текст видят и могут отменить владелец и администраторы, но критическое выполнение подтверждает только владелец: он обязан сверить устройство, оболочку, полный текст сценария, план отката и хеш.

## Модель безопасности

- Личный токен создаёт и отзывает только владелец или администратор. Техник и наблюдатель не могут использовать Codex через RemoteIt.
- Каждый владелец или администратор видит и отзывает только собственные токены. Отключение учётной записи или понижение роли сразу блокирует ранее выданные токены.
- Токен имеет только ограниченные scope: чтение устройств, планирование, создание, чтение и отмена собственных действий.
- Секрет токена хранится только на доверенном компьютере администратора; Agent его не получает.
- Изменяющее действие нельзя подтвердить через MCP.
- Критические действия, включая универсальные сценарии, подтверждает только владелец.
- Подписанный конверт привязан к ID задания, ID устройства, типу, нормализованным параметрам, времени, nonce и SHA-256 хешу запроса.
- Agent закрепляет первый публичный ключ сервера и отклоняет незаметную замену ключа.
- Nonce записывается на диск до выполнения, чтобы повторная доставка не повторила действие.
- Вывод ограничен по размеру и сохраняется вместе с автором, источником и временем.
- Отзыв токена немедленно прекращает новые запросы этой интеграции.

## Ротация и отзыв

Если токен потерян или компьютер администратора больше не доверенный:

1. Отзовите интеграцию в панели RemoteIt.
2. Создайте новый токен.
3. Удалите старый MCP-сервер командой `codex mcp remove remoteit` и добавьте его заново с новым токеном.
4. Проверьте журнал действий за период возможной компрометации.

## Перенос на другой сервер

Для переноса нужны исходный код/образ приложения, база PostgreSQL, переменные окружения и значение `REMOTEIT_ACTION_SIGNING_SECRET`. Потеря этого секрета создаёт новый ключ подписи; уже установленные Agent намеренно отклонят его как неожиданную замену. Ротация ключа должна быть отдельной подтверждённой процедурой, а не обычным обновлением.

## Диагностика

- «Недействительный токен» — токен истёк, отозван или введён не полностью.
- «Контур подписанных действий отключён» — на сервере не задан `REMOTEIT_ACTION_SIGNING_SECRET` длиной не менее 32 символов.
- «Публичный ключ изменился» — Agent обнаружил замену ключа; не удаляйте закрепление до проверки переноса сервера.
- «Ожидает подтверждения» — откройте карточку задания в RemoteIt, проверьте устройство, параметры, хеш и план.
- «Истекло» — создайте новый план; просроченное подписанное задание не выполняется.
