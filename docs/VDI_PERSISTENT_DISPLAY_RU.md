# Постоянный экран RemoteIt на RDS/VDI

## Почему отключённый пользователь иногда не имеет кадра

RemoteIt жёстко закрепляет устройство за SID пользователя. Это исключает прежнюю ошибку, при которой многопользовательский VDI мог показать кадр другого человека. Однако после полного отключения RDP Windows может удалить `Microsoft Remote Display Adapter` закреплённого сеанса. Сам сеанс и процессы остаются, но графической поверхности, которую можно безопасно захватывать, уже нет.

Перезапуск захвата, DXGI/GDI fallback и повторное открытие `winsta0` помогают после переподключения адаптера, но не могут создать отсутствующий монитор.

## Production-решение

Основной режим должен использовать подписанный `RemoteIt Virtual Display` на VDI-хосте:

1. системная служба создаёт виртуальный монитор через Windows Indirect Display Driver (IddCx);
2. монитор остаётся в закреплённом SID-сеансе независимо от физического RDP-клиента;
3. Agent продолжает выбирать только сохранённый SID и никогда не переходит к активному соседнему пользователю;
4. DXGI захватывает виртуальный монитор тем же низколатентным путём;
5. отключение драйвера возвращает текущую схему без изменения пользователей и RDP-настроек.

Драйвер должен быть подписан для целевых Windows Server/Windows 10–11. Неподписанный тестовый драйвер и включение test-signing для production недопустимы.

## Почему не используется автоматический `tscon` / `WTSConnectSession`

`WTSConnectSession` подключает существующий сеанс к другой WinStation и требует пароль, если целевой сеанс принадлежит другой учётной записи. На многопользовательском VDI это может вытеснить живое подключение, вывести сеанс на консоль или нарушить границу между пользователями. RemoteIt поэтому не соединяет закреплённый SID с произвольным активным сеансом и не хранит доменный пароль на сервере панели.

## Дополнительный RDP-bootstrap

Если виртуальный драйвер установить нельзя, допустим отдельный, явно включаемый владельцем режим `Пробудить VDI по RDP`:

- пароль передаётся непосредственно целевому Agent по зашифрованному административному каналу и не попадает в базу панели, журнал или MCP;
- при выборе `запомнить` секрет хранится только на самом VDI-хосте, зашифрованный Windows DPAPI с машинной областью, с возможностью немедленного удаления;
- подключение разрешено только к локальному VDI-хосту, только для SID, уже закреплённого за устройством;
- перед показом кадра Agent повторно проверяет SID нового сеанса;
- bootstrap имеет тайм-аут, состояние и кнопку отмены; не подключается к чужой активной WinStation.

Такой режим является fallback, а не заменой виртуального дисплея: он зависит от политики RDP/NLA, лицензирования RDS и состояния домена.
