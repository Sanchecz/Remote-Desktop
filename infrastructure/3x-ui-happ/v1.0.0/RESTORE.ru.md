# Перенос и восстановление `v1.0.0`

Полное восстановление изменяет системные файлы. Выполняйте его только в согласованное окно и сначала создайте отдельный бэкап целевого сервера. В комплекте намеренно нет команды, которая без проверки перезаписывает весь `/`.

## Что сохраняет старые ссылки Happ

Для продолжения работы прежних ссылок необходимо сохранить одновременно:

- `/etc/x-ui/x-ui.db`, где находятся клиенты, UUID, `sub_id`, inbounds и параметры подписок;
- прежнее DNS-имя и внешний порт подписки;
- TLS-сертификат и ключ либо новый корректный сертификат для того же имени;
- неизменный путь выдачи подписки;
- DNS-запись, которую переключают на новый сервер только после локальной проверки.

Если URL подписки использует домен, смена DNS не меняет сам URL. Если в URL жёстко записан старый IP, сохранить ссылку при потере этого IP можно только через переходный reverse proxy или сохранение старого адреса.

## 1. Скачать assets приватного релиза

В GitHub Release `v1.0.0` находятся:

- `portable-current-main-20260813T124133Z.tar.gz.xuibak`;
- `portable-current-node2-20260813T124235Z.tar.gz.xuibak`;
- `3x-ui-happ-v1.0.0-kit.zip`;
- `SHA256SUMS-release.txt`.

Сначала сверить SHA-256 каждого загруженного файла с `SHA256SUMS-release.txt`.

## 2. Проверить комплект

После распаковки `3x-ui-happ-v1.0.0-kit.zip`:

```bash
cd v1.0.0
python3 scripts/verify_release.py
```

## 3. Расшифровать архив

Нужны Python 3 и пакет `cryptography`. Пароль вводится скрыто и не попадает в историю shell:

```bash
python3 scripts/backup_crypto.py decrypt \
  /path/to/portable-current-main-20260813T124133Z.tar.gz.xuibak \
  /root/portable-main.tar.gz

python3 scripts/backup_crypto.py decrypt \
  /path/to/portable-current-node2-20260813T124235Z.tar.gz.xuibak \
  /root/portable-node2.tar.gz
```

## 4. Провести безопасный аудит

Аудит ничего не восстанавливает: он проверяет пути внутри tar, внутренние SHA-256, роль снимка, SQLite и обязательные файлы.

```bash
bash scripts/audit_portable_backup.sh /root/portable-main.tar.gz main
bash scripts/audit_portable_backup.sh /root/portable-node2.tar.gz node2
```

Оба запуска должны закончиться `AUDIT_OK`.

## 5. Подготовить новые серверы

- использовать архитектуру `x86_64`;
- сверить ОС и версии с `OS-RELEASE.txt` и `VERSIONS.txt` внутри снимка;
- не менять SSH-доступ старых серверов во время подготовки;
- сохранить отдельный снимок чистого нового сервера;
- проверить занятость портов по `LISTENERS.txt`;
- сравнить firewall и маршруты по диагностическим файлам;
- заранее уменьшить DNS TTL, но ещё не переключать запись.

## 6. Предварительно извлечь данные

```bash
install -d -m 700 /root/restore-stage
tar -xzf /root/portable-main.tar.gz -C /root/restore-stage
```

В верхнем каталоге снимка находятся `snapshot/` и диагностические файлы. Критичные данные:

- `snapshot/etc/x-ui`;
- `snapshot/usr/local/x-ui`;
- `snapshot/etc/systemd/system/x-ui.service`;
- сертификаты и ACME-состояние;
- служебная конфигурация OpenAI-маршрута;
- `STATE.txt`, `LISTENERS.txt`, `ROUTES.txt`, `IPTABLES-v4.txt`, `IPTABLES-v6.txt` и `NFTABLES.txt`.

## 7. Применить в окно работ

1. Ещё раз создать бэкап целевого сервера.
2. Остановить только `x-ui` на новом целевом сервере.
3. Скопировать проверенные каталоги из `snapshot/` с сохранением владельцев и прав.
4. Не копировать вслепую firewall и сетевые правила: адаптировать их к новому провайдеру и адресам.
5. Выполнить `systemctl daemon-reload`.
6. Оставить `openai-chain-*-healthcheck.timer` в состоянии `disabled`/`inactive`.
7. Запустить `x-ui`.
8. Выполнить тест Xray: `xray-linux-amd64 run -test -c bin/config.json`.
9. До DNS-переключения проверить локально панель и подписку через временную запись `hosts` или отдельное тестовое имя.
10. Проверить по одному профилю каждого используемого протокола.
11. Проверить три последовательных обновления Happ и два повторных подключения Telegram.
12. Только после этого переключить DNS.

Для копирования допустим `rsync -aHAX --numeric-ids`, но нельзя применять `--delete` или копировать весь корень без просмотра точного источника и назначения.

## 8. Два узла и смена IP

Если меняется IP основного узла, на втором узле требуется обновить endpoint служебного WireGuard outbound и правила firewall/ACL, затем проверить только OpenAI-трафик и обычный выход второго узла. Ключи WireGuard можно сохранить.

Если меняется IP второго узла, основной WireGuard peer обычно продолжает распознавать его по публичному ключу. Проверить всё равно нужно: firewall/ACL могли ограничивать старый исходный адрес.

После смены любого IP проверить DNS, TLS, firewall, OpenAI trace, обычный trace второго узла, Telegram, российские direct-домены и три последовательных обновления Happ.

## 9. Откат переноса

До переключения DNS откат заключается в отказе от переключения. После переключения вернуть DNS на старый сервер и дождаться TTL. Старые серверы и снимки не удалять, пока не проверены все подписки, протоколы и клиентские сценарии.
