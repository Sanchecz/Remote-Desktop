# Инструкция Codex для будущих выпусков без пароля

## Обязательные ограничения

- начинать с read-only диагностики;
- не менять SSH-доступ, пароли, URL подписок, UUID, `sub_id`, inbounds и клиентов без прямого отдельного указания;
- перед production-правкой создавать переносимый снимок затрагиваемого узла;
- заранее называть точный файл/настройку, изменение и откат;
- не перезапускать широко сервер и не переустанавливать 3x-ui;
- не возвращать `geosite:*`/`geoip:*` и внешние GEO URL без отдельной проверки;
- не включать автоматику, периодически меняющую runtime Xray;
- не коммитить базу, ключи или полный backup в Git-историю.

## Доступ к резервным копиям

Владелец выбрал хранение без пароля. Codex должен:

1. Перед каждым выпуском подтвердить, что репозиторий `PRIVATE`.
2. Проверить список collaborators и pending invitations.
3. Если появился кто-либо кроме владельца — не публиковать raw-архив и сообщить владельцу.
4. Размещать `.tar.gz` только как private Release asset, никогда не через `git add`.
5. После публикации снова проверить приватность и collaborators.
6. Скачать asset обратно через GitHub и сверить SHA-256.
7. Не вставлять содержимое базы, сертификатов или ключей в документацию и логи.

## Снять новый бэкап

На каждом узле использовать актуальный `portable-backup.sh`:

```bash
bash scripts/portable-backup.sh main
bash scripts/portable-backup.sh node2
```

Проверить:

- `tar -tzf`;
- `DB-INTEGRITY.txt`;
- `STATE.txt`;
- `SNAPSHOT-SHA256SUMS.txt`;
- `audit_portable_backup.sh`;
- локальный и серверный SHA-256.

Архив копировать локально по SSH с проверенным host key и сверять SHA после копирования.

## Проверить рабочее состояние

До и после изменения:

- PID x-ui и Xray;
- `systemctl is-active/is-enabled`;
- SQLite `integrity_check`;
- Xray `run -test`;
- все подписки: HTTP 200, непустой ответ, единый routing, интервал 1 час;
- routing SHA и отсутствие GEO refs;
- три обновления Happ и повторные подключения Telegram со стороны владельца.

## Собрать новую версию

1. Создать новый каталог `infrastructure/3x-ui-happ/vX.Y.Z/`.
2. Извлечь routing из свежей SQLite-копии, а не из старого локального файла.
3. Добавить русские README, RELEASE_NOTES, RESTORE, VALIDATION, SECURITY, этот runbook и памятку.
4. Создать `SHA256SUMS.txt` только для безопасных отслеживаемых файлов.
5. Просканировать Git-каталог на IP серверов, SSH-пароли, UUID, subscription URL, private-key заголовки, `.db`, `.key`, `.pem`, `.tar.gz`.
6. Собрать ZIP документации отдельно от репозитория.
7. Создать `SHA256SUMS-release.txt` для ZIP и raw `.tar.gz`.

## Опубликовать

1. `git fetch origin --prune`.
2. Создать ветку `agent/3xui-happ-vX.Y.Z` от свежего `origin/main`.
3. Добавить только каталог новой версии.
4. Проверить staged diff и выполнить commit.
5. Push, draft PR, проверка, ready, merge.
6. Создать новый стабильный Release, не переиспользуя старый tag.
7. Приложить ZIP, raw main/node2 `.tar.gz`, manifest.
8. Проверить `draft=false`, `prerelease=false`, Latest, размеры и GitHub-side digest.
9. Скачать manifest и хотя бы один asset обратно из Release; сверить SHA.
10. Повторно подтвердить private-статус, единственного collaborator и отсутствие invitations.

## Если Codex видит публичный репозиторий

Немедленно прекратить публикацию raw-бэкапа. Не загружать секреты. Сначала владелец должен вернуть private-статус и оценить, не были ли существующие assets доступны посторонним. Если были — считать ключи внутри архивов потенциально скомпрометированными.
