# Хранение без пароля

Владелец осознанно выбрал свободный доступ к резервным копиям через свой приватный GitHub без отдельного пароля.

## Модель доступа

Защита raw-архивов теперь равна защите GitHub-аккаунта и private-репозитория. На момент выпуска:

- видимость: `PRIVATE`;
- collaborator: только `Sanchecz`;
- pending invitations: 0.

## Что находится внутри `.tar.gz`

- база 3x-ui;
- UUID и `sub_id` пользователей;
- сертификаты и приватные ключи;
- Reality/WireGuard и служебные настройки;
- файлы, достаточные для переноса инфраструктуры.

Поэтому raw-архивы:

- не добавляются в Git-историю;
- не должны пересылаться или публиковаться;
- размещаются только как private Release assets;
- требуют включённой двухфакторной аутентификации GitHub и защищённого устройства владельца;
- нельзя оставлять на общем компьютере после скачивания.

## Что делать при расширении доступа

Перед добавлением collaborator нужно понимать: он получит возможность скачать архивы и все секреты внутри. Если такой доступ не нужен, не добавлять collaborator. Если репозиторий нужно сделать публичным, сначала удалить raw-assets из Release и учитывать, что удаление не отменяет уже сделанные загрузки.

## Что проверять Codex

Codex перед и после каждого выпуска проверяет private-статус, collaborators, invitations, GitHub-side SHA и отсутствие raw-архивов в commit. Если эти условия не выполнены, публикация должна быть остановлена.
