# Хранение переносимых архивов без отдельного пароля

Владелец выбрал прямой доступ к raw-бэкапам через private GitHub Release. Архивы не зашифрованы дополнительным паролем.

## Что защищает архивы

- приватность `Sanchecz/Remote-Desktop`;
- аутентификация GitHub-аккаунта владельца;
- отсутствие raw-архивов в Git history;
- публикация только как private Release assets.

Рекомендуется включённая двухфакторная аутентификация GitHub и защищённое устройство владельца.

## Что находится внутри `.tar.gz`

- база 3x-ui;
- UUID, `sub_id` и данные пользователей;
- сертификаты и приватные ключи;
- Reality/WireGuard и служебная конфигурация;
- файлы x-ui/Xray и systemd;
- данные, достаточные для переноса двухузловой инфраструктуры.

Поэтому доступ к Release равен доступу к секретам внутри архивов.

## Обязательные правила

- не коммитить `.tar.gz`, `.db`, `.key`, `.pem`;
- не делать репозиторий публичным;
- не добавлять collaborators без намерения дать им доступ ко всем секретам;
- не пересылать архивы через публичные файлообменники;
- всегда сверять SHA-256 после скачивания;
- перед публикацией и после неё проверять `PRIVATE`, collaborators и pending invitations;
- при фактической утечке считать ключи потенциально скомпрометированными.

Удаление asset после утечки не отменяет уже выполненные скачивания. Сначала сохранить рабочую точку, затем планировать контролируемую ротацию.
