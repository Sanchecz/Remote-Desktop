# Восстановление `v1.0.3` на другом сервере

Raw-архивы private Release не имеют отдельного пароля. Для скачивания нужен доступ владельца к приватному репозиторию.

## 1. Скачать и проверить

Из Release `v1.0.3` скачать:

- `3x-ui-happ-v1.0.3-kit.zip`;
- нужный `portable-pre-v1.0.3-*.tar.gz`;
- `SHA256SUMS-release.txt`.

Сверить контрольные суммы:

```bash
sha256sum -c SHA256SUMS-release.txt
```

Затем выполнить audit из распакованного kit:

```bash
bash v1.0.3/scripts/audit_portable_backup.sh /path/to/archive.tar.gz main
bash v1.0.3/scripts/audit_portable_backup.sh /path/to/archive.tar.gz node2
```

Запускать только соответствующую архиву роль. Ожидаемый результат — `AUDIT_OK`.

## 2. Что сохраняет старые ссылки Happ

Главный источник истины — `/etc/x-ui/x-ui.db`. Для продолжения работы старых URL также сохранить:

- прежний host, port и path подписки;
- TLS-сертификат и DNS-запись, если используется домен;
- UUID, `sub_id`, клиентов и назначения;
- настройки `subEncrypt` и `subUpdates`.

Если ссылка содержит старый IP, новый IP нельзя подставить незаметно без сохранения старого адреса или промежуточного reverse proxy. Для домена можно переключить DNS после проверки нового узла.

## 3. Восстановить полную базу

1. Сделать snapshot нового сервера.
2. Старый сервер не выключать и DNS заранее не переключать.
3. Распаковать архив в каталог с правами `0700`.
4. Сверить версии, listeners, маршруты и firewall.
5. Остановить только x-ui на новом сервере.
6. Восстановить `/etc/x-ui`, `/usr/local/x-ui`, unit-файл, сертификаты и необходимые служебные файлы с сохранением владельцев и прав.
7. Не копировать вслепую интерфейсы, публичные адреса и firewall.
8. Выполнить `systemctl daemon-reload` и запустить x-ui.
9. Оставить старые автоматические healthcheck-таймеры выключенными.

## 4. Применить routing `v1.0.3`

Raw-архивы являются точкой непосредственно до изменения routing. Сначала собрать проверенный deeplink:

```bash
python3 v1.0.3/scripts/build_happ_link.py \
  v1.0.3/routing/RoscomVPN.routing.json \
  --output /tmp/RoscomVPN.deeplink.txt --print-hashes
```

Затем установить его в основной 3x-ui:

```text
subEnableRouting=true
subRoutingRules=<пусто>
subIncyEnableRouting=true
subIncyRoutingRules=<содержимое RoscomVPN.deeplink.txt>
subUpdates=1
```

Перед записью сделать отдельную копию SQLite. Не изменять UUID, `sub_id`, клиентов или inbounds. После применения выполнить только узкий контролируемый restart x-ui, если он необходим для чтения настройки из памяти.

## 5. Проверить до переключения трафика

- SQLite `integrity_check=ok`;
- x-ui/Xray active;
- Xray `run -test` → `Configuration OK`;
- все подписки возвращают HTTP `200` со строгим TLS;
- Base64-тело декодируется;
- в теле ровно один `happ://routing/add/...`;
- заголовок `Routing` отсутствует;
- `Routing-Enable: true` и интервал `1`;
- deeplink SHA совпадает с `09bd9a...09283`;
- Happ импортирует полную подписку;
- Telegram проверен на Wi-Fi и мобильной сети;
- российский direct и зарубежный proxy проверены раздельно.

Только после этого переключать DNS/адрес. Старый сервер оставить доступным для быстрого отката.

## 6. Известные ограничения

- `v1.0.3` не гарантирует мгновенный reconnect Telegram в Happ Android;
- банковское приложение может определять сам системный VPN-интерфейс даже при `DIRECT`;
- межсерверный OpenAI/WireGuard-обход не является частью активной конфигурации и не должен включаться автоматически.
